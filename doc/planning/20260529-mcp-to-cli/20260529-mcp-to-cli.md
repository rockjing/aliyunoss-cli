## 技术画像

- **语言/运行时**: TypeScript, Node.js >= 18, ESM。
- **核心依赖**: `ali-oss`, `dotenv`, `zod`, 当前仍依赖 `@modelcontextprotocol/sdk`。
- **构建工具**: `tsc`。
- **测试工具**: Jest + ts-jest，已补充 CLI、配置、安全校验、脱敏和删除确认相关测试。
- **入口现状**: `src/cli/index.ts` 为 `aliyunoss-cli` 主入口；`src/index.ts` 通过 `aliyunoss-cli stdio` / `--stdio` 保留 MCP stdio 兼容。
- **能力现状**: CLI 已暴露上传、临时 URL、列表、复制、元数据查询、删除、批量删除、配置校验、健康检查和 stdio 兼容入口。

## 专家视角

- **Node.js CLI 工程**: 需要设计命令入口、参数解析、退出码、stdout/stderr 和 JSON 输出契约。
- **云存储安全**: 需要统一 object key 校验、删除确认、批量删除 dry-run，防止误删和路径绕过。
- **配置与密钥管理**: 需要拆分运行时密钥配置与脱敏公开配置，避免内部日志或错误输出泄漏密钥。
- **迁移架构**: 需要在保留可验证 OSS 能力的同时，减少 MCP Tool 与 CLI 命令的重复逻辑。
- **测试/发布工程**: 需要更新 `bin`、脚本、发布文件列表和文档，并补齐 CLI 参数与安全测试。

## 推荐方案

采用分阶段迁移：先抽出安全与配置基础能力，再建立 CLI 框架，随后迁移普通命令和危险删除命令，最后处理兼容、文档与验证。

优先保持 `OSSStorageService` 作为底层适配层。CLI 命令不直接调用 `ali-oss` SDK，而是通过存储服务完成操作。MCP 旧入口是否保留作为兼容能力，放在后期独立决策，避免第一阶段同时改动协议入口和业务能力。

## 设计模式触发

- **Command Pattern**: CLI 每个子命令独立为命令模块，便于参数校验、测试和后续扩展。
- **Adapter/Facade**: 继续以 `OSSStorageService` 屏蔽 `ali-oss` SDK 细节。
- **Centralized Validation**: 新增统一 object key 校验模块，替代各工具内分散的 `isValidFileName`/`isValidPrefix`。
- **Presenter/Formatter**: 用统一输出模块处理文本与 `--json` 输出，控制错误结构和退出码。

过度设计风险：当前 CLI 只有 7 个核心命令，不建议引入复杂插件系统或多层命令总线；参数解析库也应选轻量稳定方案，避免迁移范围膨胀。

## 范围控制

本轮包括：

- 迁移文档中列出的 7 个 OSS 能力到 `aliyunoss-cli`。
- 修复 object key 路径遍历、删除无确认、密钥公开访问三类风险。
- 建立 CLI 输出、退出码、帮助信息和 JSON 输出契约。
- 更新 npm bin、脚本、README/部署文档和测试。

本轮不包括：

- 图形界面、Web UI 或交互式文件管理器。
- OSS Bucket 策略、RAM 权限策略、服务端回收站能力。
- 未在当前工具列表中实际暴露的 ACL、分片上传等扩展命令。
- 自动推送、发布 npm 包或变更远端配置。

## 阶段策略与暂停点

1. **安全基础阶段**: 完成 object key 统一校验和密钥脱敏边界。暂停点：Review 安全规则是否过严或影响现有合法 key。
2. **CLI 框架阶段**: 完成 `aliyunoss-cli` 命令入口、参数解析、输出与错误处理。暂停点：Review 命令命名和退出码契约。
3. **能力迁移阶段**: 迁移上传、URL、列表、复制、元数据等普通命令。暂停点：Review 输出字段是否满足脚本集成。
4. **危险操作阶段**: 迁移删除和批量删除，加入确认、dry-run 和 yes。暂停点：必须 Review 删除确认体验。
5. **收尾验证阶段**: 更新文档、测试、打包配置和兼容策略。

## 关键风险

- object key 校验若过严，可能拒绝合法 OSS key；需要测试覆盖边界样例。
- 删除 `--yes` 支持脚本场景，但可能绕过人工确认；需要明确只在显式传入时生效。
- `ConfigManager.getConfig()` 现状会返回包含密钥的浅拷贝；迁移时要避免破坏已有初始化流程。
- 如果最终移除 MCP 入口，需要同步删除 SDK 依赖和旧文档；建议作为后续决策点。
- 当前项目无现成测试文件，补测试可能需要先稳定 Jest/ts-jest 配置。
